# 시프기_포인터_무한소수계산기

자릿수 제한 없이 **사칙연산(+, -, *, /)** 을 오차 없이 계산하는 C 언어 계산기입니다.
`int`나 `double`을 쓰지 않고 수를 직접 자릿수 배열·연결리스트로 다루기 때문에, 수백~수천 자리 정수와 긴 소수도 정확하게 계산합니다.
나눗셈은 분수로 계산하고 끝나지 않는 소수는 순환마디를 괄호로 표시합니다.

```
Input  : 324134341341413.319434913*2123291392139123.39123921+1321321.43234342
Result : 688231656866907303054803484014.95912391200853873

Input  : (-22)/7
Result : -3.(142857)
```

- 언어: C (C 표준 라이브러리만 사용, 외부 라이브러리 없음)
- 원본 프로젝트: [JJongmen/InfCal](https://github.com/JJongmen/InfCal)

### 순환소수 표기
- 반복되는 부분(순환마디)을 괄호로 감쌉니다: `1/3 = 0.(3)`, `1/7 = 0.(142857)`, `31449/9999 = 3.(1452)`
- 소수점 아래 출력이 10000자리를 넘으면(순환마디든, 2·5 인수가 많은 긴 유한소수든) 10000자리까지만 출력하고 끝에 `...`을 붙입니다. 내부 값은 분수라서 정확하고, 출력만 줄인 것입니다.

| `(` 바로 뒤에 `*`, `/` | `(*3)` | `(-3)`, `(+3)` |

- 공백은 **숫자 사이를 제외하고** 어디에 넣어도 됩니다. 검사 후 모두 제거하고 계산합니다.
  - 허용: `( -1 ) + 2`, `2 * ( 3 + 4 )`, `2   *   3`(연속 공백)
  - 공백이 낀 생략 곱셈도 처리합니다: `3 (4)` → 12, `(1+2) (3+4)` → 21
  - 금지: `1 2`(숫자 두 개가 공백으로 떨어져 있으면 잘못된 식)
- 맨 앞이나 `(` 바로 뒤의 `+`, `-`는 부호로 인식합니다: `-5+1`, `(-3)*2`
- 식의 맨 앞/끝 공백은 무시합니다: ` -3+5` → 2, `1+2 ` → 3
- 0으로 나누면 `divide by zero`를 출력합니다: `5/0`, `5/(3-3)`
- 줄바꿈(`\n`), 탭(`\t`), 캐리지리턴(`\r`), 수직탭(`\v`), 폼피드(`\f`)는 모두 공백처럼 취급합니다: `1\t+\t2` → 3
- 파일을 끝까지 읽어 여러 줄을 한 식으로 이어 붙입니다: `1+2`(줄바꿈)`+3` → `1+2+3` = 6
  - 단, 두 식을 줄바꿈으로만 나눈 경우(`1+2`(줄바꿈)`9*9`)는 숫자 사이 공백이 되어 잘못된 식으로 처리됩니다.
- 메모장으로 저장한 파일의 UTF-8 BOM은 무시합니다.
- 입력 파일을 안 주거나 열 수 없으면 사용법 / `cannot open file` 메시지를 출력하고 종료 코드 1로 끝납니다.
- 모든 오류 메시지(`wrong expression`, `divide by zero`, `cannot open file`, `out of memory`, 사용법)는 **표준 에러(stderr)** 로 출력합니다. 정상 결과(`Result : ...`)만 표준 출력(stdout)으로 나갑니다.
- 종료 코드: 정상 계산은 0, 오류(식 오류 · 0으로 나누기 · 파일/인자 오류 · 메모리 부족)는 1입니다.

## 동작 흐름

```
파일 입력 → 연결리스트 저장 → 유효성 검사 → 식 다듬기 → 후위표기식 변환 → 분수 계산 → 소수로 출력
  calc.c       linklist.c        check.c      change.c       postfix.c        rational.c
```

1. **입력** (`calc.c`): 파일에서 수식을 한 글자씩 읽어 문자 연결리스트에 저장합니다.
2. **검사** (`check.c`): 위 입력 규칙을 검사합니다.
3. **다듬기** (`change.c`)
   - 부호 처리: `-1` → `0-1`, `(-1` → `(0-1`
   - 곱셈 생략 보완: `3(4)` → `3*(4)`, `(2)(3)` → `(2)*(3)`, `(2)3` → `(2)*3`
4. **후위표기 변환** (`postfix.c`): 연산자 스택으로 우선순위(`* /` > `+ -`)와 왼쪽 결합을 처리합니다.
5. **계산** (`rational.c`): 후위식을 스택으로 계산합니다. 모든 값은 기약분수(부호, 분자, 분모)입니다.
6. **출력** (`rational.c`): 분수를 소수로 바꾸고 순환마디에 괄호를 칩니다.

## 구현 원리 (이론과 알고리즘)

계산기는 크게 세 층으로 나뉩니다.

```
[식 처리]    중위표기 → 후위표기 변환, 스택으로 계산          (postfix.c, change.c)
[분수 연산]  모든 값을 기약분수 p/q 로 두고 + - * / 수행     (rational.c)
[큰 자연수]  자릿수 제한 없는 자연수의 + - * / 와 gcd        (rational.c)
```

### 1. 수의 표현: 왜 분수인가

- 소수 `0.1`이나 `1/3`은 2진 부동소수(`double`)로 정확히 표현할 수 없어서, 계산할수록 오차가 쌓입니다.
- 그래서 모든 값을 **유리수 `부호 × p / q`** 로 저장합니다. `p`(분자)와 `q`(분모)는 크기 제한이 없는 자연수입니다.
- 사칙연산은 유리수에 대해 닫혀 있어서(0으로 나누기만 빼면), 결과도 항상 정확한 유리수입니다.
  그래서 `1/3*3 = 1`, `1/3+1/6 = 0.5`가 오차 없이 나옵니다.

**불변식 (항상 지키는 규칙)**
- `q > 0`이고 `gcd(p, q) = 1`(기약분수)입니다. 부호는 따로 `+1/-1`로 들고 있습니다.
- 0은 항상 `+0/1` 하나로만 표현합니다(`-0`이 나오지 않도록).

**입력 변환**: 소수점 아래가 `k`자리인 수는 `정수 / 10^k`입니다.
`123.45 = 12345/100`이고, 바로 약분해서 `2469/20`으로 저장합니다.

### 2. 큰 자연수: 위치 기수법

수를 `BASE = 10000`진법 배열로 저장합니다. 칸 하나에 10진 4자리가 들어갑니다.

```
123456789  =  1·10000² + 2345·10000¹ + 6789·10000⁰   →   d = [6789, 2345, 1]  (낮은 칸부터)
```

**10000진법을 고른 이유**
- 칸끼리 곱해도 `9999 × 9999 < 10⁸`이라 `int`에 들어가고, 많이 더해도 `long long`이면 넘치지 않습니다.
- 10의 거듭제곱이라 10진수로 출력할 때 칸마다 4자리씩 그대로 찍으면 됩니다(진법 변환 불필요).
- 10000은 2와 5로 나누어떨어집니다. 그래서 어떤 수가 2나 5로 나누어떨어지는지는 **가장 낮은 칸만 보면** 알 수 있습니다(순환마디 계산에 사용).
- 1자리씩 저장할 때보다 곱셈 반복이 약 16배, 덧셈·비교가 약 4배 줄어듭니다.

#### 2-1. 덧셈·뺄셈 — 받아올림과 받아내림
초등학교 세로셈과 같습니다. 낮은 칸부터 더하고, `BASE` 이상이면 다음 칸으로 1을 올립니다.
뺄셈은 큰 수에서 작은 수를 빼며, 음수가 되면 `BASE`를 빌려옵니다. 둘 다 **O(n)** 입니다.

#### 2-2. 곱셈 — 세로셈(합성곱)
`a`의 i번째 칸과 `b`의 j번째 칸의 곱은 결과의 `i+j`번째 칸에 더해집니다.

```
c[i+j] += a[i] × b[j]      (모든 i, j)
```

- 모든 칸 곱을 `long long` 배열에 먼저 모으고, 올림은 마지막에 한 번에 처리합니다(1024행마다 중간 정리해서 오버플로를 막음).
- 시간 복잡도는 **O(n·m)** 입니다.

#### 2-3. 나눗셈 — 긴 나눗셈과 몫 추정
손으로 하는 긴 나눗셈을 칸 단위로 합니다. 나머지 `R`에 다음 칸을 내려 붙이고(`R = R × BASE + 다음 칸`), 그 칸의 몫 `q`(0~9999)를 구해 `R -= q × b`를 합니다.

몫 한 칸을 0부터 9999까지 하나씩 시도하면 느리기 때문에 **어림한 뒤 보정**합니다.

1. `R`의 상위 3칸과 `b`의 상위 2칸을 실수로 나눠 `q`를 어림합니다.
2. `q × b > R`이면 `q`를 1씩 줄이고, `R - q × b ≥ b`이면 1씩 늘립니다.

- 보정 단계가 있어서 어림이 조금 틀려도 **결과는 항상 정확**합니다. 상위 2칸으로 나누면 어림 오차는 보통 0~2 정도라 보정은 몇 번이면 끝납니다.
- 항상 `R < b`를 유지하므로 한 칸을 내려 붙여도 `R < b × BASE`이고, 몫 한 칸은 `0 ~ BASE-1` 범위에 들어갑니다.
- 나뉘는 수의 상위 `(b의 길이 - 1)`칸은 몫이 0이 확실하므로 한 번에 복사합니다. 그래서 비용은 **O((a의 길이 - b의 길이 + 1) × b의 길이)**, 즉 몫의 길이에 비례합니다.

#### 2-4. 최대공약수 — 유클리드 호제법
분수를 약분하려면 `gcd`가 필요합니다.

```
gcd(a, b) = gcd(b, a mod b),   gcd(a, 0) = a
```

- **원리**: `a = b·k + r`이면 `a`와 `b`의 공약수는 `b`와 `r`의 공약수와 같습니다. 그래서 큰 수 문제를 작은 수 문제로 계속 줄여 나갈 수 있습니다.
- 반복 횟수는 자릿수에 비례합니다(라메의 정리: 피보나치 수가 최악의 경우).
- 각 단계의 나눗셈 비용이 몫 길이에 비례하므로(2-3), 몫 길이를 모두 더해도 전체 비용은 **O(n²)** 입니다.

### 3. 분수의 사칙연산

#### 3-1. 덧셈·뺄셈 — 최소공통분모
`a/b ± c/d`에서 분모끼리 그냥 곱하면 `b·d`가 되어 수가 빨리 커집니다. 대신 `g = gcd(b, d)`로 최소공배수를 분모로 씁니다.

```
b' = b/g,  d' = d/g
a/b ± c/d  =  (a·d' ± c·b') / (b·d')        ← b·d' 가 lcm(b, d)
```

결과를 약분할 때 `gcd(분자, b·d')` 전체를 구할 필요 없이 **`gcd(분자, g)`만 구하면 됩니다.**

> **이유**: `gcd(a, b) = gcd(c, d) = 1`이고 `gcd(b', d') = 1`입니다.
> 어떤 소수 `p`가 `b'`와 분자 `a·d' ± c·b'`를 동시에 나눈다고 해 봅시다.
> `p`는 `c·b'`를 나누므로 `a·d'`도 나눠야 합니다. 그런데 `p`가 `b'`(따라서 `b`)를 나누니 `a`는 못 나누고, `d'`도 못 나눕니다. 모순입니다.
> `d'`에 대해서도 똑같습니다. 그래서 분자와 분모의 공약수는 `g` 안에만 있을 수 있습니다.
> (Knuth, *The Art of Computer Programming* Vol.2, 4.5.1절)

부호가 다를 때는 두 분자의 크기를 비교해서 큰 쪽에서 작은 쪽을 빼고, 큰 쪽의 부호를 붙입니다.

#### 3-2. 곱셈 — 교차 약분
`(a/b) × (c/d)`를 곱하기 **전에** 대각선끼리 약분합니다.

```
g1 = gcd(a, d),  g2 = gcd(c, b)
(a/b) × (c/d)  =  ((a/g1)·(c/g2)) / ((b/g2)·(d/g1))
```

입력이 기약분수라 `a`와 `b`, `c`와 `d`는 이미 서로소입니다. 대각선 공약수까지 없앴으니 결과는 **약분 없이 바로 기약분수**입니다. 곱하기 전에 작게 만들어서 곱셈과 gcd 비용도 줄어듭니다.

#### 3-3. 나눗셈 — 역수 곱하기
```
(a/b) ÷ (c/d)  =  (a/b) × (d/c)
```
`c = 0`이면 `divide by zero` 에러입니다. 그 외에는 3-2의 교차 약분 곱셈을 그대로 씁니다.

### 4. 분수를 소수로: 순환소수 이론

#### 4-1. 자릿수 뽑기
`p/q`의 정수 부분은 `p ÷ q`의 몫이고, 나머지 `r`로 소수 자리를 한 자리씩 만듭니다.

```
r ← r × 10
다음 자리 = r ÷ q 의 몫 (0~9)
r ← r mod q
```

나머지가 0이 되면 유한소수로 끝납니다.

#### 4-2. 언제 끝나고, 언제 반복되나
기약분수 `p/q`의 분모를 `q = 2^a × 5^b × m`(`m`은 2, 5와 서로소)으로 나누면:

- `m = 1`이면 **유한소수**입니다. 소수점 아래 자릿수는 `max(a, b)`입니다. (`10 = 2 × 5`라서 `10^k`로 분모를 없앨 수 있음)
- `m > 1`이면 **순환소수**입니다.
  - 순환하지 않는 앞부분 길이는 `max(a, b)`입니다.
  - 순환마디 길이는 `10^k ≡ 1 (mod m)`이 되는 가장 작은 `k`입니다. 이 값을 **10의 위수(multiplicative order)** 라고 부르고, `m - 1` 이하입니다.

| 식 | 분모 분해 | 앞부분 | 순환마디 | 결과 |
|---|---|---|---|---|
| `1/8` | 2³ | 3 | 없음 | `0.125` |
| `1/6` | 2 × 3 | 1 | 1 (10 ≡ 1 mod 3) | `0.1(6)` |
| `1/7` | 7 | 0 | 6 | `0.(142857)` |
| `31449/9999` (= `953/303`) | 3 × 101 | 0 | 4 (= lcm(1, 4)) | `3.(1452)` |

#### 4-3. 순환마디 찾기
1. 분모에서 2와 5의 개수를 세서 앞부분 길이 `max(a, b)`를 구하고, 그만큼 자리를 먼저 출력합니다.
2. 그 시점의 나머지 `r₀`를 기억합니다. `m`이 10과 서로소라서 이후 나머지는 반드시 **`r₀`로 다시 돌아옵니다**(순수 순환).
3. 나머지가 `r₀`가 될 때까지 자리를 뽑고, 그 구간을 괄호로 감쌉니다.

나머지를 전부 저장해 두고 비교할 필요 없이 **`r₀` 하나만 기억하면** 됩니다. 순환마디가 10000자리를 넘으면 그만 뽑고 `...`을 붙입니다.

### 5. 식 처리

#### 5-1. 단항 부호와 곱셈 생략 (`change.c`)
- 맨 앞이나 `(` 바로 뒤의 `-x`, `+x`는 `0-x`, `0+x`로 바꿉니다. 그러면 모든 연산자를 이항 연산자로만 다룰 수 있습니다.
- `3(4)`, `(2)(3)`, `(2)3`처럼 숫자·괄호가 붙어 있으면 사이에 `*`를 넣습니다.

#### 5-2. 중위 → 후위 표기 변환 — Shunting-yard 알고리즘 (`postfix.c`)
다익스트라의 Shunting-yard 알고리즘입니다. 연산자를 스택에 잠시 두었다가 우선순위에 맞게 내보냅니다.

- 숫자는 바로 출력합니다.
- 연산자를 만나면, 스택 맨 위 연산자의 **우선순위가 같거나 높은 동안** 꺼내서 출력한 뒤 자신을 넣습니다.
  - 우선순위: `* /` (2) > `+ -` (1)
  - "같아도 꺼낸다" 덕분에 **왼쪽부터 계산(왼쪽 결합)** 이 됩니다: `100/10/5 = (100/10)/5 = 2`
- `(`는 스택에 넣고, `)`를 만나면 `(`가 나올 때까지 꺼내 출력합니다.

```
10-2*3+1   →   10 2 3 * - 1 +   →   5
```

#### 5-3. 후위 표기 계산 — 스택
왼쪽부터 읽으며 숫자는 스택에 넣고, 연산자를 만나면 두 개를 꺼내 계산한 결과를 다시 넣습니다. 먼저 꺼낸 것이 오른쪽 피연산자입니다(`a - b`, `a / b`의 순서 보장). 끝나면 스택에 하나만 남아야 하고, 아니면 잘못된 식입니다.

### 6. 시간 복잡도 요약

`n`, `m`은 자릿수(칸 수)입니다.

| 연산 | 알고리즘 | 복잡도 |
|---|---|---|
| 자연수 덧셈·뺄셈·비교 | 받아올림/받아내림 | O(n) |
| 자연수 곱셈 | 세로셈(합성곱) | O(n·m) |
| 자연수 나눗셈 | 긴 나눗셈 + 몫 추정 | O((n−m+1)·m) |
| 최대공약수 | 유클리드 호제법 | O(n²) |
| 분수 덧셈·뺄셈 | 최소공통분모 + gcd(분자, g) | gcd와 곱셈 비용 |
| 분수 곱셈·나눗셈 | 교차 약분 | gcd와 곱셈 비용 |
| 소수 출력 | 한 자리씩 긴 나눗셈 | 출력 자릿수 × O(분모 길이) |
| 식 변환·계산 | Shunting-yard + 스택 | O(식 길이) |

### 7. 메모리 관리
- 큰 자연수 배열은 부족할 때만 용량을 **2배씩** 늘리고(`realloc`) 버퍼를 재사용합니다. 그래서 긴 나눗셈이나 소수 출력에서 자리마다 `malloc`하지 않습니다.
- 계산에 쓴 중간값은 연산이 끝나면 바로 해제하고, 입력·후위식·결과 연결리스트도 프로그램 끝에서 모두 해제합니다.
- **검증 방법**: `malloc`/`calloc`/`realloc`/`free`를 가로채는 진단용 빌드로 모든 테스트를 돌렸습니다.
  - 해제되지 않은 블록 수와 잘못된(이중) `free`를 셉니다.
  - `free`할 때 메모리를 쓰레기 값으로 덮어써서, 해제한 메모리를 다시 읽는 코드가 있으면 결과가 달라지게 했습니다.
  - 결과: 테스트 57개 모두 **누수 0, 잘못된 free 0, 해제 후 사용 의심 0**.
